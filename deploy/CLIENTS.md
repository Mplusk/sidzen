# Клиенты: аккаунты и покупатели из заказов

ЛК → «Клиенты» (`/account/clients/`), также доступен из навигации управления.
Просмотр использует право `customers.read`, удаление/восстановление — отдельное
`customers.write` (администратор и superadmin; sales только просмотр).
Покупатели, гости и отключённые аккаунты не получают доступ к чужим данным;
просмотр клиентов не даёт права менять роли пользователей.

Показываются все аккаунты и контакты из неудалённых заказов без регистрации.
Повторные гостевые заказы объединяются по паре email + телефон (пробелы/регистр
email, оформление телефона и российский префикс 8/7 нормализуются). Совпадение
только одного поля не объединяет людей. Совпавшая полная пара с аккаунтом не
дублируется, но связь владения заказом и права доступа НЕ меняются. Для аккаунта
пустые ФИО/телефон дополняются только из заказа с тем же userId, без изменения
профиля. Аккаунты для входа и пароли гостям автоматически не создаются.

Список по 50 записей без общего лимита, стабильная сортировка, согласованный
снимок count + данных. Тип карточки виден рядом с контактами.

Удаление с подтверждением добавляет обратимую запись `ClientArchive`; «Удалённые»
позволяет восстановить карточку. Заказы, отправления, финансы, аккаунты и права
входа не меняются. Это не полное стирание персональных данных: соответствующие
запросы по-прежнему обрабатываются в отдельном разделе. Аудит операции содержит
хеш ключа карточки, а не контактные данные. Новые деплои не восстанавливают
удалённые карточки. Ключ гостевой карточки — SHA-256 пары контактов, а не сами
email/телефон. В `ClientArchive` контактные данные в открытом виде не записываются.

Только серверное чтение необходимых полей; пароли, секреты, сессии, OAuth-id,
адреса и внутренние заметки не загружаются. Страница приватная и закрыта от индексации.
Проверки: page unit tests и `scripts/smoke-clients-http.ts` в локальной `shop_qa`.
