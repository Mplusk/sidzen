# Общие счётчики SIDZEN

С 18.10.2026 персональный мониторинг отключён. В `/account/monitoring/` остались только суточные итоги по публичным страницам и карточкам товаров. Право просмотра — `monitoring.read`, очистки — `monitoring.clear` с подтверждением. Очистка всех счётчиков не касается заказов, аккаунтов и других журналов. Старые фильтры IP/страна и история посетителей отсутствуют.

`MonitoringCounter`: DATE по Москве, публичный путь, необязательный ID публичного товара, BIGINT количества просмотров. Ключ — дата + путь. Нет отдельных событий, точных времён, IP, геолокации, источника, поисковых запросов, браузера, устройства, cookie, идентификатора посетителя/визита/сессии или связи с аккаунтом. Визиты, уникальные люди, длительность и последовательность переходов не вычисляются. Повторное открытие страницы повышает счётчик.

Клиент отправляет только `{path}` на `/api/page-views/`, с `credentials: omit` и `referrerPolicy: no-referrer`. Нет записи в browser storage, heartbeat или отслеживания взаимодействий. Предзагрузка Next.js не считается просмотром; скрытая вкладка учитывается только при показе. Запрет отслеживания DNT/GPC учитывается. Это приблизительные открытия страниц: без JavaScript, при блокировке запросов, сетевой ошибке или превышении общего лимита часть открытий не попадёт в счётчик. Посещения администратора публичных страниц не отделяются от остальных — для этого не читаются сессии.

Сервер не обращается к авторизации и не читает cookies/IP. Строгая схема тела, максимум 1 КБ, проверка Origin и один глобальный временный лимит 600 запросов/минуту без индивидуальных ключей. Частные маршруты и query запрещены. Произвольные slug не сохраняются: категория/товар должны существовать и быть публичными. Нет внешних счётчиков или геолокационных API. Тела и заголовки запросов не логируются. В Caddy access logging не включён. Техническая обработка IP для сетевого соединения/безопасности магазина — отдельная цель, не история посещений.

Каждый час worker удаляет счётчики старше 30 календарных дней. Операции очистки/увеличения сериализованы advisory lock. Администратор видит итоги за сегодня, 7 или 30 календарных дней, таблицу страниц и общие дневные суммы. Идентификаторов для восстановления истории конкретного посетителя нет.

## Переход со старой версии

Миграция `20261018120000_aggregate_page_views` удаляет персональные визиты, страницы и согласия из рабочей БД; в аудите сохраняются только количества удалённых записей. Пустые старые таблицы оставлены для совместимости при rollback приложения, но INSERT/UPDATE запрещены триггерами БД. Они не представлены в новом Prisma-клиенте. Старые вкладки получают 410 на `/api/monitoring/`; endpoint прежнего согласия только удаляет `sidzen_statistics` и не разрешает сбор даже с `?choice=allow`. Новый клиент удаляет старые статистические ключи localStorage/sessionStorage, не затрагивая корзину и вход.

Из старых событий не создаются новые агрегаты. Старые резервные копии выбывают по действующей ротации до 14 дней. Любое восстановление выполняется с актуальными миграциями до открытия публичного доступа (см. OPERATIONS.md): пропуск миграции/отключение блокирующих триггеров недопустимы. Не возвращайте в эксплуатацию старую персональную аналитику. JSON-аудит операции не заменяет подписанный оператором акт уничтожения.
