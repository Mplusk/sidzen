# Категоризация DeepSeek

ЛК администратора → Подключения магазина → DeepSeek · категории товаров.
API key хранится AES-GCM в группе `integrations`, не попадает в публичные
настройки, браузер, аудит или диагностические логи. Проверка использует
`GET https://api.deepseek.com/models` без генерации текста. Включение разрешено
только после успешной проверки выбранной модели.

После включения новые ручные товары и новые карточки импорта Ozon/WB ставятся
в PostgreSQL-очередь. Старые товары остаются в режиме MANUAL. Для пересчёта
существующего товара выбрать «Автоматически · DeepSeek» в форме и сохранить.
Сохранение в режиме AI всегда запускает новый расчёт; ручное изменение
основной категории автоматически выбирает MANUAL и отменяет ожидающую задачу.
Новый товар без категории сохраняется как черновик, не публикуется до
назначения категории. Статусы товара, наличие, цены и фотографии ИИ не меняет.

Фоновый цикл независим от импорта, платежей и доставки. Внешний HTTP-запрос
выполняется вне транзакции: 25 секунд, максимум 3 попытки временных ошибок с
отложенными повторами. У задачи lease и generation; ручной выбор, новые данные
или новая конфигурация исключают применение устаревшего ответа. Просроченный
lease восстанавливается после перезапуска. После изменения категорий worker
сбрасывает кеш каталога через защищённый внутренний endpoint, повторяя сброс
при недоступном приложении.

Классификация: `POST https://api.deepseek.com/chat/completions`, JSON Output,
thinking disabled, 256 output tokens, модель из закрытого списка
deepseek-flash / deepseek-v4-pro. Ответ валидируется: существующий ID обязан
быть в каталоге, новое название — текст 2–80 символов без HTML/URL. Категории
сверяются повторно перед записью: регистр, ё/е, пробелы и пунктуация не создают
дубль. Скрытые категории не включаются автоматически. Семантические синонимы
не гарантируются: при неверном результате оператор может исправить категорию
вручную. Максимум 500 категорий — при превышении задача требует ручного выбора,
список не обрезается молча. Дополнительные категории сохраняются.

Передаются только название (180 символов), короткое описание (500), описание
(3500) и ID/названия/родители категорий. Не передаются записи пользователей,
заказы, характеристики произвольного формата, себестоимость, фото или модели.
Распространённые email, телефоны, URL и токены в тексте маскируются; это не
заменяет проверку оператором публичного контента на отсутствие персональных
данных. DeepSeek — внешний сервис: оператор должен передавать только
обезличенные публичные сведения о товарах. Запросы оплачиваются владельцем
API key по тарифу DeepSeek.

Логи → DeepSeek · категории: успех/ошибка, число попыток и закрытый код причины,
без тела запросов/ответов. Деталь задачи и безопасное объяснение видны в форме
товара. Неверные ответы не уничтожают предыдущую категорию.

Документация API: https://api-docs.deepseek.com/api/create-chat-completion/
Тесты: `pnpm test`, `scripts/smoke-category-ai.ts`,
`scripts/smoke-category-ai-http.ts` (только local shop_qa, синтетический транспорт).

## Качество выбора категории

Приоритет — основное назначение и конкретный тип товара из названия, а не материал, декоративный дизайн или 3D-печать. Для настольного светильника подходящая категория — «Настольные светильники», не общий «Декор» и не «Прототипы». Если есть лишь общий раздел, разрешённый режим создания позволяет предложить конкретную категорию. Ручной выбор по-прежнему защищён от последующей категоризации.

Однократное исправление семи проверенных светильников: `scripts/fix-table-lamp-categories.ts`. По умолчанию только проверяет данные; применение требует `APPLY_CATEGORY_CORRECTION=1`. Требует существующую видимую категорию, все семь ожидаемых артикулов и отсутствие активного импорта. Назначает основную категорию, включает MANUAL, отменяет ожидающие AI-задачи и сохраняет аудит; цены, статусы и остатки не меняются. У опубликованного товара прежняя ссылка из «Декора» сохраняется дополнительной категорией.
