# Аварийное восстановление входа администратора

Применяется только к версии с `security.admin_email_confirmation` и таблицей `AdminLoginChallenge`. Это аварийная операция: она временно отключает второй фактор для всего персонала. Документ не является разрешением выполнять изменения на production.

1. Подтвердите личность владельца и неисправность почтовой доставки, согласуйте окно обслуживания и восстановление с владельцем. Сначала попробуйте восстановить доставку или доступ к почте администратора; не передавайте коды, ссылки и пароли через чаты.
2. Убедитесь, что у владельца есть действующий пароль активного суперадминистратора и защищённый канал доступа к серверу. Проверьте текущий релиз и схему на соответствие SQL ниже. Создайте и проверьте свежую резервную копию по действующей процедуре. Без проверенной копии и согласования владельца не продолжайте.
3. Отключите входящий доступ к приложению на время обслуживания и остановите все процессы приложения, фоновые процессы и любые другие записи в эту базу, оставив PostgreSQL доступным только оператору. Не возобновляйте трафик до фиксации транзакции. Это необходимо, чтобы одновременно не создавались новые сессии или запросы подтверждения.
4. В подключении к **проверенной production-базе** выполните транзакцию ниже с `ON_ERROR_STOP=1`. Она отменяет сессии всех пользователей с административными правами, уничтожает ожидающие подтверждения, отключает защиту и добавляет запись в аудит. Пароли и покупательские сессии не изменяются. Не подставляйте в неё адреса, токены или личные данные.

```sql
BEGIN;
DO $$
BEGIN
  IF NOT EXISTS (
    SELECT 1 FROM "SiteSetting"
    WHERE "key" = 'security.admin_email_confirmation' AND "value" = 'true'::jsonb
  ) THEN
    RAISE EXCEPTION 'Expected enabled admin email confirmation setting';
  END IF;
END $$;

DELETE FROM "Session" s
WHERE EXISTS (
  SELECT 1 FROM "UserRole" ur
  JOIN "Role" r ON r.id = ur."roleId"
  WHERE ur."userId" = s."userId"
    AND (r.code = 'superadmin' OR EXISTS (
      SELECT 1 FROM "RolePermission" rp WHERE rp."roleId" = r.id
    ))
);
DELETE FROM "AdminLoginChallenge";
UPDATE "SiteSetting" SET "value" = 'false'::jsonb, "updatedAt" = CURRENT_TIMESTAMP
WHERE "key" = 'security.admin_email_confirmation';
INSERT INTO "AuditLog" (id, "actorId", action, "entityType", "after", "createdAt")
VALUES (gen_random_uuid()::text, NULL, 'security.admin-email.emergency-disable',
        'SiteSetting', '{"enabled":false,"reason":"offline-recovery"}'::jsonb, CURRENT_TIMESTAMP);
COMMIT;
```

При любой ошибке выполните `ROLLBACK` и разберите причину; не выполняйте выборочные части транзакции. После успеха восстановите работу сервисов и трафика, проверьте вход владельца по паролю, смените скомпрометированные учётные данные при необходимости и запишите событие в журнал инцидентов. Защита остаётся выключенной для всех сотрудников до устранения причины и повторного безопасного включения с подтверждением доставки. Проверьте, что старые привилегированные сессии и ссылки больше не действуют.
