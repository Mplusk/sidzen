# Точка + CloudKassir · АУСН Доходы · без НДС

Точка принимает деньги картой / СБП. Сайт создаёт платёжную ссылку **без чека**; CloudKassir отдельно получает запросы на фискализацию. Параллельную выдачу чеков в Точке необходимо отключить. Сервис Точки «Чеки» не используется: он недоступен для АУСН.

## Что заполнить в личном кабинете

В **Доставка и оплата → CloudKassir · онлайн-касса**:

1. Public ID сайта и API Secret из CloudKassir / CloudPayments. Это не ключ Точки. Секрет хранится зашифрованным, не выводится в HTML или журнал.
2. ИНН продавца, совпадающий с разделом «Реквизиты магазина» и регистрацией кассы.
3. Заводской номер ККТ (DeviceNumber) и 16-значный номер ФН (FiscalNumber), выданные CloudKassir после подключения и регистрации рабочей кассы.
4. Подтверждения рабочей кассы, настройки налогов и проверки договоров / оснований обработки данных. Эти подтверждения заполняет продавец, сайт их не подставляет автоматически.
5. «Разрешить автоматические чеки» → «Проверить кассу и сохранить».

Проверка вызывает только `/test` и `/kkt/state/get`: не выпускает чек, не принимает оплату и не регистрирует / перенастраивает ККТ. Проверяется доступ, ИНН, касса и ФН, фискализация, онлайн-состояние, отсутствие блокировки, действующий ФН и место расчётов `sidzen.shop`. Настройку СНО ККТ нужно отдельно подтвердить у CloudKassir: проверка состояния не возвращает её.

В **Точка · интернет-эквайринг → Чеки** выбрать **CloudKassir · АУСН Доходы · без НДС**. Сохранённые банковские ключи не меняются. Новая онлайн-оплата в этом режиме доступна только после включения и проверки кассы.

Система налогообложения кассы фиксирована: `TaxationSystem=1`, соответствующий УСН «Доходы» для АУСН «Доходы». НДС — `Vat=null`, **не** `0` (0 означает НДС 0%). Режимы налогообложения и ставки из формы кассы Точки в этом сценарии не используются.

## Уведомления и цикл чеков

В кабинете CloudKassir включить уведомление **Receipt**, POST, формат `ключ=значение`, адрес:

`https://sidzen.shop/api/fiscal/cloudkassir/`

Проверяется `Content-HMAC` над исходными URL-кодированными байтами (HMAC SHA-256, API Secret). Не использовать декодированную подпись `X-Content-HMAC` для сырого тела. Связь проверяется по InvoiceId, ID чека, ИНН, типу, сумме и фискальному составу. Повторные уведомления не создают новые чеки. Без уведомлений работает фоновая проверка статуса.

- **Предоплата 100%**: после проверки статуса `APPROVED` в Точке. Авторизация / холд не являются оплатой. Один чек на заказ, товары — предмет расчёта 1, способ расчёта 1; скидка распределяется точно в копейках. Бесплатная доставка не добавляется как платная позиция.
- **Полный расчёт**: администратор открывает заказ, устанавливает `DELIVERED` и подтверждает фактическую передачу товара покупателю. Доставка в ПВЗ / передача перевозчику не равны получению. Кассе передаётся способ расчёта 4, зачёт предоплаты на всю сумму, без нового электронного списания. Проверяется подтверждённая оплата и отсутствие неразобранного частичного возврата.
- **Полный возврат**: деньги возвращает продавец через банк. Сайт не инициирует денежные возвраты. После проверки банковского `REFUNDED` кассе отправляется `IncomeReturn` по исходному составу. Чек возврата ожидает завершения предыдущих чеков. Если ранее обнаружен частичный возврат либо оплата впервые обнаружена уже возвращённой, требуется ручная сверка вместо автоматических чеков.
- **Частичные возвраты, коррекции, старые заказы и оплата по счёту**: продавец оформляет необходимые чеки вручную в кассе. Сайт не угадывает возвращённые позиции и суммы и не фискализирует исторические заказы повторно.

В карточке заказа администратора — состояния чеков, ошибки, InvoiceId для поиска и кнопка сверки. Покупатель видит готовые чеки в заказе / подтверждении заказа; CloudKassir направляет электронный чек на email заказа. Отсутствие чека не отменяет подтверждённую оплату, но требует внимания продавца.

## Сбои и защита от дублей

Запрос с email хранится зашифрованным и неизменным. На каждый тип чека — одна запись, один InvoiceId и один X-Request-ID. База защищает конкурентные клики / процессы. Очередь сохраняется между релизами.

Сверка банка и кассы выполняется отдельным циклом фонового процесса: длительная синхронизация каталога и запросы перевозчику её не задерживают. При остановке контейнера текущий финансовый запрос завершается перед отключением базы; после сбоя незавершённую попытку подхватывает сохранённая очередь.

CloudKassir хранит результат идемпотентного запроса **один час**. При потере ответа повторяем строго тот же запрос только в пределах 45 минут от первой попытки. Позже запись переводится в ручную сверку; новый запрос / ключ автоматически не создаются. Если ID известен, запрашиваем статус, а не повторную выдачу.

Для уже пробитого чека можно указать его ID в блоке ручной сверки: сайт только читает статус и детализацию API, сверяет InvoiceId, ИНН, тип, сумму, налоги, состав и способ оплаты. Несовпадение или недостаточная детализация запрещают привязку. Неизвестный / отклонённый чек нельзя «починить» слепой повторной выдачей: сначала проверка в CloudKassir, затем согласованное ручное оформление / коррекция.

Отключение интеграции запрещает новые платежи в режиме CloudKassir, но не прекращает уже возникшие обязательства по чекам. Смена терминала / ИНН при незавершённых чеках или оплаченных заказах блокируется. Заказы с обязательной историей чеков нельзя удалить. Ключ того же терминала можно обновить.

## Данные и проверка

CloudKassir получает только email, позиции, суммы, налоговые реквизиты и технический ID чека. Не передаются имя, телефон, адрес доставки, пароль, токены входа или карта. База и резервные копии магазина должны находиться в России; оператор проверяет договоры с CloudKassir / ОФД и законные основания обработки. Код сайта не заменяет организационные обязанности по 152-ФЗ и регистрации ККТ.

Unit-тесты и `scripts/smoke-cloudkassir.ts` проверяют расчёты, НДС, подписи, PostgreSQL-конкуренцию, цикл предоплаты / зачёта / возврата, потерю ответа, срок идемпотентности, сверку без повторного чека и отключение. `scripts/smoke-cloudkassir-http.ts` проверяет права, шифрование ключей, формы и запреты. Все провайдеры синтетические; настоящие чеки и списания в этих проверках не создаются. Полный рабочий сценарий требует ваших ключей, зарегистрированной ККТ и отдельно согласованной проверки с реальным расчётом.

Источники: [CloudKassir API](https://developers.cloudkassir.ru/), [разъяснение ФНС о коде СНО ККТ для АУСН](https://www.nalog.gov.ru/rn25/ifns/r25_17/info/16635865/).
