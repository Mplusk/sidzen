# Вход через Google, VK ID и Яндекс ID

Настройки: личный кабинет администратора → «Доставка и оплата» → «Вход через Google, ВКонтакте и Яндекс». Право `settings.write`; ключи не связаны с Seller / Delivery API. По умолчанию все провайдеры выключены. Кнопки появляются только для включённых, заполненных подключений.

Для каждого сервиса создайте собственное приложение для `sidzen.shop`, задайте адрес возврата **с завершающим слешем**:

| Сервис | Redirect URI | Что заполнить |
| --- | --- | --- |
| Google | `https://sidzen.shop/api/auth/social/google/callback/` | Веб-клиент, Client ID, Client Secret; права openid/email/profile |
| VK ID | `https://sidzen.shop/api/auth/social/vk/callback/` | Веб-приложение VK ID, App ID; право email, PKCE, без старого OAuth VK |
| Яндекс ID | `https://sidzen.shop/api/auth/social/yandex/callback/` | Client ID, Client Secret; права login:info и login:email |

Сохраните настройки, отметьте проверку оператором правил обработки и включение кнопки. Сохранение не проверяет пароль приложения: действительность ключей и Redirect URI проверяется полным входом в реальный аккаунт провайдера. Пока приложений нет, обычный вход работает, неработающие кнопки не показываются. Секрет вводится один раз; пустое поле сохраняет прежний секрет только при неизменном Client ID. Смена ID не переносит старые идентификаторы пользователей и отменяет незавершённые попытки входа. Можно выключить провайдера или удалить секрет. Перед сменой / отключением обеспечьте покупателям альтернативный доступ; социальные аккаунты без пароля иначе не смогут начать новый вход.

## Обработка данных

Функционал не является юридическим заключением о соответствии всему 152-ФЗ. Оператор проверяет договоры, получателей, локализацию, уведомления и применимые ограничения. Google дополнительно заблокирован серверным `GOOGLE_OAUTH_LEGAL_APPROVED=false`: изменение на true допустимо **только после реальной проверки и выполнения применимых требований**, не ради обхода проверки. Размещение основной базы и резервных копий в РФ остаётся обязательным. Не подключайте Google, если правовые основания не подтверждены. Приложения и организационные уведомления нельзя зарегистрировать от имени продавца автоматически без его участия.

Нет сторонних JS SDK, виджетов, фонового входа, загрузки аватаров или аналитики: браузер переходит к провайдеру только после отдельной пустой отметки согласия и нажатия кнопки. Первичная запись на сервере в РФ содержит состояние и снимок согласия. При первой регистрации покупатель подтверждает имя / контактный email и отдельное согласие кабинета; пароль магазина необязателен. Можно задать его впоследствии в профиле. Токены доступа и обновления не сохраняются; временный профиль зашифрован и удаляется после регистрации либо по истечении десятиминутной попытки.

## Защита и проверка

State и PKCE S256, случайный httpOnly/Secure/SameSite=Lax cookie с префиксом __Host- в production (без Domain, защита от подмены поддоменом), одноразовый атомарный захват callback, десятиминутный TTL и версия подключения. Google JWT: RS256/JWKS, issuer, audience, exp, iat, nonce, azp. VK: device_id, echoed state и совпадение user_id ответа токена и user_info; Яндекс: client_id ответа user_info. Сервер обращается только к фиксированным HTTPS адресам, без перенаправлений и с таймаутами. Ответы провайдеров и ошибки с токенами не логируются.

Идентификатор `(provider, clientId, subject)` определяет аккаунт. **Совпадение email никогда не объединяет кабинеты**, не даёт права администратора и не подтверждает владение email. При занятом email нужно войти обычным способом и привязать сервис из профиля. Привязка требует исходной активной сессии, а при наличии пароля — его повторного ввода; запрет замены чужой привязки и переключения уже вошедшего браузера. Новые кабинеты получают только роль customer. Удаление привязки требует подтверждения, не позволяет удалить последний доступный способ без пароля, завершает другие сессии. При отзыве согласия через раздел персональных данных внешние привязки удаляются и новые входы через них прекращаются.

Автотесты используют только синтетические данные / подменённые ответы. Без реальных приложений и разрешённого пользовательского входа нельзя заявлять проверку реального OAuth round-trip, модерации Google / VK или прав Яндекс. После настройки проверьте новый вход, отказ в согласии у провайдера, повторный вход и привязку к существующему кабинету в отдельном браузере, не меняя аккаунт администратора.

Источники: [Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect), [официальный VK ID SDK](https://github.com/VKCOM/vkid-web-sdk/blob/master/src/auth/auth.ts), [Яндекс code/PKCE](https://yandex.ru/dev/id/doc/ru/codes/code-url), [Яндекс user_info](https://yandex.ru/dev/id/doc/ru/user-information), [портал Роскомнадзора](https://pd.rkn.gov.ru/cross-border-transmission/).

Размер 180×40, надпись встроена в контуры, без внешних шрифтов и SDK. [Правила оформления Google](https://developers.google.com/identity/branding-guidelines). Не заменяйте фирменный знак обычной буквой G.
